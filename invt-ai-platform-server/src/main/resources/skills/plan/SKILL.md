# 计划模式

当用户想要计划而非执行时使用此技能。

## 核心行为

本轮对话中，你只做规划。

- 不要实现代码。
- 除计划 markdown 文件外，不要编辑项目文件。
- 不要运行会改变状态的终端命令，不要 commit、push 或执行外部操作。
- 需要时，可以用只读命令/工具检查仓库或其他上下文。
- 你的交付物是一份保存到当前工作区 `.invt/plans/` 下的 markdown 计划。

## 输出要求

撰写的 markdown 计划应具体且可执行。

根据需要包含以下内容：
- 目标
- 当前上下文 / 假设
- 拟采用方案
- 分步计划
- 可能变更的文件
- 测试 / 验证
- 风险、权衡与待确认问题

如果任务涉及代码，请包含确切的文件路径、预计的测试目标和验证步骤。

## 保存位置

用 `write_file` 将计划保存到：
- `.invt/plans/YYYY-MM-DD_HHMMSS-<slug>.md`

视为相对于当前工作目录 / 后端工作区的路径。Agent 文件工具已感知后端，因此使用此相对路径可在本地、Docker、SSH、Modal 和 Daytona 等后端上保持计划与工作区一致。

如果运行时提供了特定目标路径，则使用该确切路径。
否则，自行在 `.invt/plans/` 下创建一个带时间戳的合理文件名。

## 交互风格

- 如果需求足够清晰，直接撰写计划。
- 如果 `/plan` 没有附带明确指令，则从当前对话上下文推断任务。
- 如果确实不够具体，简要提出一个澄清性问题，而不是猜测。
- 保存计划后，简要回复你做了什么计划以及保存路径。
